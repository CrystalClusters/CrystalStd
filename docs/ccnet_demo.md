# ccnet 交互演示

`ccnet` 的可运行示例：一个服务端、一个客户端，均以交互命令驱动。服务端支持多客户端接入，并把每个客户端的数据转发给其他客户端；客户端收到的数据只写入环形缓冲区，`refresh` 时显示最新未读，因此不会打断命令行输入。

> 模块接口与语义见 [ccnet](ccnet.md)。演示源码位于 `demo/ccnet/`，构建产物由目录自动检索生成。

## 1. 构建与运行

```bash
./build.sh                # Linux：生成 out/<平台>_bin/ccnet_server_demo 与 ccnet_client_demo
build.bat                 # Windows：生成 out\<平台>_bin\ccnet_server_demo.exe 与 ccnet_client_demo.exe
```

运行：

```bash
./run_demo.sh                    # 菜单选择
./run_demo.sh ccnet_server
./run_demo.sh ccnet_client
```

```bat
run_demo.bat                     :: 菜单选择
run_demo.bat ccnet_server
run_demo.bat ccnet_client
```

不带参数时进入菜单，输入序号运行；直接回车、`0` 或 `q` 可不运行直接退出。`run_demo.* --list` 只列出 `out/<平台>_bin` 下所有 `*_demo` 产物。服务端与多个客户端分别占用一个终端窗口。

## 2. 快速演示

服务端：

```text
srv> listen 9000
[完成] 正在监听 0.0.0.0:9000
srv[on=0 u=1]> status
```

客户端 A：

```text
cli[off u=0]> connect 127.0.0.1 9000
[完成] 已连接 127.0.0.1:9000（第 1/1 条）
cli[on u=1]> send hello-from-A
```

客户端 B：

```text
cli[off u=0]> connect localhost 9000
[解析] localhost:9000 -> 2 条，用时 0.8 ms
  1) [::1]:9000 (IPv6)
  2) 127.0.0.1:9000 (IPv4)
[尝试] [::1]:9000
  失败：REFUSED (-7)
[尝试] 127.0.0.1:9000
[完成] 已连接 127.0.0.1:9000（第 2/2 条）
cli[on u=2]> refresh
#000001 20:59:02 <#1 127.0.0.1:54321> hello-from-A
```

客户端 A 不会收到自己发出的消息；B 的 `refresh` 中显示了服务端附加的来源 `<#1 127.0.0.1:54321>`。

## 3. 消息与来源

TCP 不保留消息边界，演示在应用层使用行协议：

```text
客户端 -> 服务端：<text>\n
服务端 -> 其他客户端：<#<id> <ip:port>> <text>\n
服务端 say：<* server> <text>\n
```

- 服务端为每条连接分配会话编号 `<id>`；
- 转发帧带来源编号与对端地址，客户端据此知道消息来自哪个连接；
- 单行上限 1023 字节；超长行截断后丢弃到下一个换行；
- 文本按字节透传，不做 UTF-8 / GBK 转码；控制字符在客户端显示前替换为 `.`。

## 4. 客户端环形缓冲区

- 容量 `128` 条，每条 `1280` 字节；
- 满时**丢最旧**，保留最新未读，并累计 `dropped`；
- 网络读线程只写缓冲区，不打印；
- 提示符显示未读数：`cli[on u=5]> `；
- `refresh` 显示全部未读；`refresh n` 只显示最新 `n` 条，并说明跳过了多少条更早消息；
- 服务端的事件也使用同样的环形缓冲区（容量 64），`refresh` 查看接入/断开/错误事件。

## 5. 服务端命令

| 命令 | 说明 |
|---|---|
| `listen <port> [bindAddr]` | 开始监听；`port=0` 使用临时端口；绑定地址必须是 IP 字面量，默认 `0.0.0.0` |
| `stop` | 停止监听，已有客户端保持连接 |
| `status` | 运行时长、监听地址、在线/峰值/累计/拒绝、收发与丢失统计 |
| `clients` | 当前连接表：ID、对端地址、状态、在线时长、收发、发送丢弃 |
| `say <text>` | 向所有客户端广播 `<* server> text` |
| `kick <id>` | 请求断开指定客户端 |
| `refresh [n]` | 显示事件缓冲区最新未读 |
| `watch [ms\|on\|off]` | 实时状态行；默认 2000ms，仅终端下输出，状态未变化时不打印 |
| `clear` | 丢弃未读事件 |
| `help` / `-h` | 帮助 |
| `quit` / `exit` | 关闭全部连接并退出 |

`watch` 由独立线程在空闲时打印一行状态并重打提示符；主线程执行命令期间会跳过，避免插进命令输出中间。

## 6. 客户端命令

| 命令 | 说明 |
|---|---|
| `connect <host> <port>` | 连接；`host` 可为域名、IPv4、IPv6 字面量；单地址 5 秒握手超时 |
| `dns <host> <port>` | 只解析并显示地址列表，不建立连接 |
| `send <text>` | 入队一条文本（上限 1023 字节），由写线程发送 |
| `spam <n> [text]` | 连续入队 `n` 条（1..10000），用于制造缓冲区/队列溢出 |
| `refresh [n]` | 显示最新未读 |
| `status` | 目标、解析来源/条数/耗时、本地/对端、收发、队列、未读与最后错误 |
| `disconnect` | 有序断开 |
| `clear` | 丢弃未读 |
| `help` / `-h` | 帮助 |
| `quit` | 断开并退出 |

### 6.1 域名解析

`connect` / `dns` 先尝试 `ccnet_addr_parse`：

- 成功：IP 字面量（含 IPv6、方括号、`%scope`），不触发 DNS；
- 返回 `CC_NET_ERR_DNS`：调用 `ccnet_dns` 获取最多 8 个地址；
- 按平台返回顺序逐个 `ccnet_tcp_connect`，首个成功即停止；
- 全部失败时报告最后一次错误。

因此 `localhost` 可能先返回 `::1`，在只监听 IPv4 的服务端上得到 `REFUSED`，随后自动回退到 `127.0.0.1`。

## 7. 线程与生命周期

| 进程 | 线程 |
|---|---|
| 服务端 | 主线程（REPL）、监听入口线程、每连接读入口线程、每连接写线程、状态 ticker |
| 客户端 | 主线程（REPL）、连接读入口线程、连接写线程 |

- 每条连接一个读入口 + 一个写线程：入口只 `recv`，写线程只 `send`，符合 `ccnet` 的一读一写并发约束；
- 服务端转发时只把帧放入目标连接的有界发送队列（8 帧），由目标自己的写线程发送；慢客户端只丢自己的帧，不阻塞其他客户端；
- 连接入口返回前会 `cc_thread_wait` 回收写线程；退出时等待监听入口、全部连接入口和 ticker 结束，再释放锁与缓冲区；
- 客户端主线程不直接调用 `ops->send` / `ops->recv`，只操作发送队列和环形缓冲区。

## 8. 颜色与输出

所有控制台输出统一走 `color_print`：

- `[完成]` 绿色、`[失败]`/错误红色、提示黄色、事件品红、信息青色、弱化信息灰色；
- 服务端状态行、连接表、客户端刷新结果都带颜色；
- `color_print` 支持 `%08llX`、`%02X`、`%-28s`、`%llu`、`%lld` 等格式，不再使用 `printf` 输出。

## 9. 限制

- 纯文本行协议，不支持二进制帧与转义；
- 不提供认证、加密、持久化、文件传输、自动重连；
- 单进程最多 32 个客户端；每条连接两个用户线程，适合演示与中小规模联调；
- `spam` 等压力操作会触发服务端发送队列丢弃，这是有界队列的预期行为；
- `watch` 在部分终端可能插在半行输入之后，可用 `watch off` 关闭；客户端永不后台打印，输入不会被接收数据打断。
