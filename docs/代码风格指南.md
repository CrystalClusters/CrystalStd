# 代码风格指南

本指南适用于 CrystalStd 与水晶簇体系的 C 项目，规定源文件组织、排版、资源生命周期、命名、注释、测试与文档的统一约定。模块文档描述具体接口语义，本指南描述跨模块一致的代码形态。

## 1. 文件与编码

- 源文件（`.c`、`.h`）统一使用 UTF-8 编码，不带 BOM。
- 换行使用 LF。Git 的 `core.autocrlf` 负责检出与提交时的换行转换，仓库中的文本内容保持 LF。
- 使用 4 个空格缩进，不使用制表符。
- Windows 下 GCC 的执行字符集由 `build.bat` 传入的编译参数决定；源码不假定执行字符集，中文字面量按 UTF-8 源文件书写。
- 构建入口为 `build.sh`（Unix Like）与 `build.bat`（Windows）。默认 DEBUG；显式传入 `release` 启用 RELEASE。编译参数由顶层脚本统一传给 `scripts/build_*` 子脚本。

目录职责：

| 路径 | 职责 |
|---|---|
| `include/` | 公共头文件 |
| `src/` | 实现文件与内部头文件 |
| `tests/` | 测试代码与测试 harness |
| `demo/` | 演示程序 |
| `docs/` | 模块文档、开发手册、快速入门 |
| `docs/tests/` | 逐用例测试文档 |
| `scripts/` | 构建子脚本 |
| `out/` | 构建产物，不提交 |

文件头使用统一注释模板：

```C
/*
 * @Author: ...
 * @Date: 2026-11
 * @LastEditors: ...
 * @LastEditTime: 2026-11
 * @Description: ...
 * Copyright (c) 2026 by lizaterop@gmail.com, All Rights Reserved.
 */
```

公共声明放在 `include/<模块>.h`；只在模块内部使用的声明放在 `src/<模块>_internal.h`；实现文件包含自己的模块头。

include 顺序：

```C
#include "ccfiles.h"
#include "ccfiles_internal.h"

#include <cc_dyn.h>
#include <crystal_cluster.h>

#include <stdio.h>
#include <string.h>
```

- 本模块的公共头与内部头使用双引号。
- 其他 CrystalStd 公共头与 C 标准库头使用尖括号。
- 三组之间空一行；同一组内按名称排序。
- 实现文件优先包含自己的模块头，保证头文件自足。

## 2. 缩进与括号

- 函数、`if`、`for`、`while`、`switch`、`struct`、`enum` 的左花括号独占一行（Allman 风格）。
- `else` / `else if` 不与上一个右花括号同行，另起一行：

```C
if (stat->type == CC_FS_TYPE_DIR)
{
    ...
}
else
{
    ...
}
```

- 单条简单语句可以省略花括号，语句相对控制语句缩进 4 空格：

```C
if (!fs)
    return CC_FS_ERR_PARAM;

for (CCUINT32 i = 0; i < count; i++)
    ccalloc(names[i], 0, NULL);
```

- 语句跨行、包含声明、包含注释或多条语句时必须使用花括号。
- `switch` 的 `case` 与 `switch` 的右花括号同列，不额外缩进：

```C
switch (stat->type)
{
case CC_FS_TYPE_FILE:
    ...
    break;

case CC_FS_TYPE_DIR:
    ...
    break;

default:
    return CC_FS_ERR_PARAM;
}
```

- `case` 分支内部使用 4 空格缩进。
- 每个 `case` 以 `break`、`return` 或 `goto` 结束；需要贯穿时显式写 `/* fall through */`。
- 空函数体写成：

```C
static void fs_noop(void)
{
}
```

不写成 `{}` 单行。

## 3. 函数定义与声明

- 返回类型、函数名、左括号在同一行。
- 参数列表超过一行时，每个参数一行，相对行首缩进 4 空格；右括号独占一行并回到第 0 列。
- 函数体左花括号另起一行。

```C
static CCINT32 fs_scan_dir_one(
    CCUINT32 parent_idx,
    const char *dir_path,
    CCDyn *stack
)
{
    ...
}
```

- 无参数函数使用 `(void)`。
- 函数声明与定义使用相同的参数顺序和类型。
- 函数原型放在 `include/` 或 `src/*_internal.h`；只在当前文件使用的辅助函数加 `static`。
- 只读输入指针加 `const`；输出参数放在参数列表末尾。
- 所有权转移、借用关系、失败时的输出状态写在接口注释或调用点附近。
- 函数长度以单一职责为准；路径构造、状态迁移、资源清理分别拆成辅助函数，不把大量细节塞进一个循环。

## 4. 声明、指针与表达式

- C99 混合声明可用，变量尽量在第一次使用处声明并初始化。
- 指针星号跟随变量：

```C
char *name;
const CCFsNode *node;
CCFiles *fs;
```

- 类型转换写成：

```C
(CCFsNode *)node
(const char *)data
(CCUINT32)stat.size
```

- `sizeof` 使用括号：`sizeof(CCFsNode)`、`sizeof(*node)`。
- 布尔值使用 `CCTRUE` / `CCFALSE`。
- 整数宽度使用 CrystalStd 类型：`CCUINT8`、`CCUINT16`、`CCUINT32`、`CCUINT64`、`CCINT32`、`CCINT64`、`CCUINTPTR`。
- 文件大小、偏移、容量使用 64 位类型；需要窄化为 `CCUINT32` 时先检查上界。
- 赋值语句需要换行时，先断在 `=` 之后，续行相对语句缩进 4 空格：

```C
CCUINT32 count =
    (CCUINT32)(stat.size / sizeof(CCUINT32));
```

- 右侧仍然过长时，再在运算符后断行，并保持同一层级缩进：

```C
CCUINT64 total =
    (CCUINT64)CC_FS_PKG_HEADER_SIZE +
    (CCUINT64)block_count * CC_FS_PKG_BLOCK_SIZE;
```

- 不写成“第一行先放一部分右侧表达式，第二行再对齐剩余部分”的混合形式。
- 其他表达式换行同样用缩进体现层级，不在同一层里一部分换行、一部分不换行。
- 单行建议不超过约 120 列；长字符串、格式串、宏和文档链接不强制拆行。

## 5. 多行函数调用

多行调用统一采用以下形式。

### 5.1 普通语句 / 赋值 / 返回

函数名后立即换行，实参相对语句缩进 4 空格，右括号回到语句缩进：

```C
    CCFsStat stat;
    CCINT32 ret = ccfiles_stat(
        fs, "/docs/开发手册.md", &stat
    );
    if (ret != CC_FS_OK)
        return ret;
```

```C
    CCINT32 pushed = cc_dyn_core_push(
        &scan_stack, (CCUINT32)sizeof(CCUINT32),
        (CCINT32)sizeof(CCUINT32), &child_idx
    );
```

```C
    return cc_rbt_core_inorder_tranverse(
        &fs_tree_ops,
        node_at(root_idx),
        out,
        fs_collect_cb
    );
```

### 5.2 控制流中的多行调用

`if` / `while` 中的调用，实参相对语句缩进 8 空格，调用右括号缩进 4 空格并接比较，外层条件右括号回到语句缩进：

```C
    if (cc_dyn_core_push(
            &scan_stack,
            (CCUINT32)sizeof(CCUINT32),
            (CCINT32)sizeof(CCUINT32),
            &child_idx
        ) != 0
    )
    {
        ret = CC_FS_ERR_NOSPACE;
        goto FailedtoPush;
    }
```

```C
    if (ccfiles_find(
            fs, "/", "*.c",
            fs_collect_cb, out
        ) != CC_FS_OK
    )
        return CCFALSE;
```

- 多行调用不在最后一行实参后直接写 `);` 或 `) != 0)`。
- 短参数可以合并到一行，按语义分组。
- 函数声明、调用、控制条件都遵循同一闭合括号规则。

## 6. `goto` 与失败标签

CrystalStd 采用“报错即退出、失败即回滚”的单出口风格，标签放在函数末尾。`goto` 只用于跨层清理和失败回滚，不用于普通循环控制。

### 6.1 成功/失败标签

`goto` 只用于失败回滚，不用于普通分支、循环控制或成功收尾。成功路径释放本函数的临时资源后直接返回，标签区只处理失败。

内部辅助函数按“参数检查 → 逐项获取 → 显式转移所有权”组织，失败标签位于函数末尾：

```C
static CCBOOL fs_mount_name(
    CCFiles *fs,
    const char *name,
    CCFsNode **out
)
{
    char *copy = NULL;
    CCFsNode *node = NULL;

    if (!fs || !name)
        goto FailedtoCheck;

    copy = (char *)ccalloc(
        NULL, (CCUINT64)strlen(name) + 1,
        CC_DBG_REL_TAG("挂载名", NULL)
    );
    if (!copy)
        goto FailedtoAllocName;

    node = (CCFsNode *)ccalloc(
        NULL, (CCUINT64)sizeof(CCFsNode),
        CC_DBG_REL_TAG("挂载节点", NULL)
    );
    if (!node)
        goto FailedtoAllocNode;

    memset(node, 0, sizeof(*node));
    node->name = copy;
    *out = node;                  // 所有权转移给调用方
    return CCTRUE;

FailedtoAllocNode:
    ccalloc(copy, 0, NULL);
FailedtoAllocName:
FailedtoCheck:
    return CCFALSE;
}
```

规则：

- 标签命名表达失败阶段：`FailedtoAllocName`、`FailedtoAllocNode`、`FailedtoWalkPath`。
- 失败发生在获取 X 时，X 的标签释放“获取 X 之前已经成功获取”的资源；不要释放获取失败的 X 本身。
- 如果获取 X 的接口可能部分成功，X 的标签先释放其内部残留，再回落到上一阶段。
- 标签从最新阶段到最早阶段排列，利用 fallthrough 逐级释放；每个资源只释放一次。
- 成功路径先释放临时资源，再直接返回；不使用 `Succeeded` / `Done` 成功标签。
- 如果成功路径与失败路径的清理动作完全相同，且成功路径没有额外的返回值转换，使用单一 `Cleanup:` 标签：成功路径自然 fallthrough，失败路径 `goto Cleanup`，标签内清理后返回 `ret`；成功时 `ret` 为 `CC_FS_OK`。标签不得命名为 `Failed` / `Done`。
- 如果成功路径需要转移资源（例如把缓冲区交给调用方），不要共用 `Cleanup`，改用静态清理辅助函数处理失败资源。
- 只有所有失败共享同一组清理资源、且没有阶段差异时，才使用通用 `Failed` 标签。
- 失败标签只出现在函数末尾；`goto` 不向前跳，不跳入带初始化变量的作用域。
- 一次调用只执行一条清理路径，不依赖重复清理，也不依赖 `ccalloc(NULL, 0, NULL)` 的空操作。
- 返回值在标签清理后返回；清理过程中不覆盖原始错误码，除非清理本身产生更严重的错误。

### 6.2 释放顺序与所有权边界

- 同一函数获取 A → B → C，失败时按 C → B → A 释放。
- 标签只释放该阶段确定获取成功的资源。
- 确定非空的指针直接释放，不在清理标签里加无意义判空。
- 可选资源、集合容器、外部输入指针按各自契约判断。
- 借用资源不释放；调用方持有的资源不由被调函数释放。
- 所有权转移必须显式：通过 `out` 参数、明确的接管接口或注释说明；转移后原持有者不再释放。
- 资源释放接口与获取接口成对：`create` / `destroy`、`mount` / `unmount`、`push` / `pop`、`ccalloc(NULL, ...)` / `ccalloc(ptr, 0, NULL)`。
- 容器或对象拥有内部资源时，通过其 `destroy` / `clear` 接口整体释放；不跨层直接释放内部字段。
- 子层只释放自己创建的资源，父层只释放子层通过接口转移给它的资源；禁止父层释放子层内部资源，也禁止子层释放父层资源。
- 失败回滚中如果需要按顺序关闭、解绑、释放，标签顺序必须与获取顺序严格相反。
- 成功路径与失败路径共享同一组清理动作时，优先使用单一 `Cleanup:` 标签 fallthrough；成功路径需要转移资源或转换返回值时，提取 `static` 清理辅助函数统一调用。不复制相同的清理块，也不为复用清理引入成功 `goto` 或成功标志。
- 清理辅助函数只接收本函数持有的资源，不接管调用方资源；辅助函数返回原始错误码或 `CC_FS_OK`，由调用点决定返回值。

资源按 A → B → C 获取时，清理标签按 C → B → A 排列：

```C
FailedtoPush:
    ccalloc(child_path.array, 0, NULL);
FailedtoBuildPath:
    ccalloc(kids.array, 0, NULL);
FailedtoCollect:
    ccalloc(root, 0, NULL);
FailedtoRoot:
    return CCFALSE;
```

### 6.3 所有权

每个资源在任意时刻必须有且只有一个明确的所有者；所有权转移必须显式发生；释放责任归最终所有者；借用者不得释放或延长资源生命周期。

- 创建者不一定永远是最终释放者；
- 接收者可以通过明确的转移取得所有权；
- 借用者可以使用资源，但不能负责它的生命周期；
- 容器成功接收元素后，容器所有者负责释放容器内的元素存储；元素为指针时，其指向的资源按接口契约归属。

| 场景 | 规则 |
|---|---|
| `ccfiles_create` 返回的探针 | 调用方持有，用 `ccfiles_destroy` 释放 |
| `ccfiles_stat` 的 `out` | 调用方提供结构体，接口只写入，不产生新所有权 |
| `ccfiles_list` / `ccfiles_find` 回调中的 `CCFsEntry` | `name` 借用节点内部字符串，只在回调期间有效，调用方不释放 |
| `ccalloc` 返回的内存块 | 调用方持有，用 `ccalloc(ptr, 0, NULL)` 释放 |
| `CCDyn` 追加元素 | 接口复制元素字节；元素为指针时，指针指向的内存归原所有者，除非契约明确转移 |
| `CCDyn` 自身的内存 | 由集合所有者用 `ccalloc(dyn.array, 0, NULL)` 释放 |
| `ccfiles_getcwd` / `ccfiles_getcur` | 写入调用方缓冲区，接口不返回内部指针 |
| `ccfiles_mount` 建立的挂载状态 | 由探针持有，`ccfiles_unmount` 或 `ccfiles_destroy` 释放 |
| `cc_rbt_core_insert` 插入的节点 | 树不复制节点；节点所有权留在调用方，移除后由调用方释放 |

成对的生命周期接口：

- `ccfiles_create` / `ccfiles_destroy`
- `ccalloc(NULL, ...)` / `ccalloc(ptr, 0, NULL)`
- `cc_rbt_core_insert` / `cc_rbt_core_remove`
- `ccfiles_mount` / `ccfiles_unmount`
- `cc_dyn_core_push` / `cc_dyn_core_pop`（元素进出）

### 6.4 `main` 的标签

成功路径直接返回；失败标签逐级回落：

```C
int main(void)
{
    CCFiles *fs = ccfiles_create();
    if (!fs)
        goto FailedtoCreate;

    if (ccfiles_mount(fs, "/m", "res", CC_FS_MOUNT_DIR) != CC_FS_OK)
        goto FailedtoMount;

    if (ccfiles_chdir(fs, "/m") != CC_FS_OK)
        goto FailedtoChdir;

    ccfiles_destroy(fs);
    return 0;

FailedtoChdir:
FailedtoMount:
FailedtoCreate:
    if (fs)
        ccfiles_destroy(fs);
    return 1;
}
```

一次运行只执行一条清理路径，不依赖重复清理。

## 7. 命名

公共符号的模块前缀统一为小写 `cc`（函数、变量、文件名）与大写 `CC`（类型、宏、枚举值）。

| 类别 | 规则 | 示例 |
|---|---|---|
| 公共类型 | `CC` 开头；模块级类型写作 `CC<模块>Xxx` 或 `CC_<模块>Xxx`，同一模块内统一 | `CCDyn`, `CCFiles`, `CCFsStat`, `CC_RbtOps` |
| 内部类型 | 模块前缀 + 小写下划线 struct 标签 | `cc_fs_node`, `cc_fs_mount`, `cc_files` |
| 枚举类型 | `CC` 开头；模块标识后接 PascalCase，同一模块内统一 | `CCFsResult`, `CCFsType`, `CC_RbtRel` |
| 枚举值 | 全大写 + 模块前缀 | `CC_FS_ERR_NOENT`, `CC_FS_TYPE_DIR`, `CC_RBT_REL_LEFT` |
| 宏 | 全大写 + 模块前缀 | `CC_FS_NIL`, `CC_FS_PKG_BLOCK_SIZE`, `CC_MEM_ALIGN_MIN` |
| 公共函数 | 模块前缀 + 小写下划线 | `ccfiles_stat`, `cc_dyn_core_push`, `cc_rbt_core_get`, `ccalloc` |
| 静态辅助函数 | 模块内前缀 + 小写下划线 | `fs_scan_dir_one`, `fs_buf_put`, `ccalloc_lock` |
| 普通变量 | 小写下划线 | `child_idx`, `watch_count`, `pkg_off` |
| 文件级静态状态 | `g_` 前缀 | `g_suites`, `g_tree_parent` |
| 回调类型 | `CC...Callback` / `CC...Visit` | `CCDataCallback` |

- `get_comment` 是 `ccalloc` 的配套查询接口，名称保持不变。
- 模块前缀与目录、头文件、测试套件保持对应，例如 `ccfiles`、`ccnet`、`ccpath`、`cc_dyn_core`、`cc_rbt_core`、`ccalloc`、`ccthread`、`cctime`、`color_print`。
- 命名表达“是什么”而不是“怎么做”。避免无意义的 `tmp`、`data2`、`foo`。
- 不使用匈牙利命名法；类型信息由声明和 `CC` 类型表达。
- 缩写保持稳定：`fs`、`dyn`、`rbt`、`pkg`、`idx`、`ptr`、`len`、`cap`。

## 8. 注释

### 8.1 注释种类

- 接口文档注释使用 `/** ... */`，用于描述公开接口的功能、参数、返回值或所有权：

```C
/**
 * 按路径读取文件元信息。
 * out 由调用方提供；接口只写结构体，不返回内部指针。
 */
CCINT32 ccfiles_stat(CCFiles *fs, const char *v_path, CCFsStat *out);
```

- 普通注释使用 `//`，不用 `/* ... */` 代替普通行注释。
- `/* ... */` 只用于文件头、内部特殊说明和大段分区标记：

```C
/* ============================================================================
 * 路径遍历：规范化、查找与目录枚举
 * ========================================================================== */
```

- 文件头使用第 1 节的块注释模板；它不是普通注释。

### 8.2 空格与对齐

- 独占一行的 `//` 注释，在 `//` 后加一个空格：

```C
// 目录节点：子节点红黑树的根下标
```

- 行尾注释与代码之间至少一个空格，`//` 后同样留一个空格：

```C
char *real_path;   // 挂载真实路径；NULL 表示跟随上级
```

- 结构体字段的尾注释可以按列对齐，便于扫描：

```C
typedef struct cc_fs_mount
{
    char *real_path;   // 真实路径（一律 `/`）
    CCUINT32 type;     // CCFsMountType
    CCUINT8 origin;    // FS_ORIGIN_*
} CCFsMount;
```

- 注释解释约束、所有权、失败后果；不重复代码字面含义。
- 资源转移、借用、释放责任必须写在接口或调用点附近。
- 中文标点与中文注释保持一致；代码标识符使用英文。
- 分配器的注释字符串使用 `CC_DBG_REL_TAG("...", NULL)`，RELEASE 下替换为 `NULL`。

## 9. 头文件

- 使用 include guard。公共头的宏名为文件名去掉 `.h`、其余 `.` 与 `-` 转 `_`、整体大写，加 `_INCLUDE_` 前缀和 `_H_` 后缀。例如 `ccfiles.h`：

```C
#ifndef _INCLUDE_CCFILES_H_
#define _INCLUDE_CCFILES_H_
...
#endif
```

- 内部头放在 `src/`，使用 `_SRC_` 或 `_INCLUDE_` 前缀、`_H_` 后缀；同一模块内统一。以 `_SRC_` 为例，`ccfiles_internal.h`：

```C
#ifndef _SRC_CCFILES_INTERNAL_H_
#define _SRC_CCFILES_INTERNAL_H_
...
#endif
```

`_H_` 是头文件后缀标记；文件名中的 `.h` 不进入宏名的文件名部分。

- 头文件只放声明、类型、宏和小型 `static inline` 工具；不放可执行的业务实现。
- 公共头文件不包含内部实现结构，不包含 `src/*_internal.h`。
- 内部状态使用不透明类型，完整定义留在 `src/`：

```C
typedef struct cc_files CCFiles;
```

- 公共头自足：使用 `CC` 类型时包含 `crystal_cluster.h`，使用 `CCDyn` 时包含 `cc_dyn.h`，不依赖调用方的包含顺序。
- 内部头可以包含公共头和其他内部头；公共头不反向依赖内部头。
- 结构体字段与初始化、清理、文档、测试保持一致。
- 头文件中的函数原型与实现使用相同的 `const`、参数顺序和返回类型。

## 10. 数据结构与内存

- 使用 `ccalloc`，不直接使用 `malloc`、`calloc`、`realloc`、`free`、`strdup`。
- `ccalloc(old, size, comment)` 同时覆盖分配、调整和释放：
  - `ccalloc(NULL, size, comment)` 分配；
  - `ccalloc(ptr, size, comment)` 调整；
  - `ccalloc(ptr, 0, NULL)` 释放。
- 分配失败返回 `NULL`；调用方必须处理，不能继续解引用。
- 动态数组使用 `CCDyn`，通过 `cc_dyn_core_push` / `cc_dyn_core_pop` / `cc_dyn_core_get` / `cc_dyn_core_set` / `cc_dyn_core_seek` 操作。
- 元素之间保存下标，不跨扩容保存元素指针。
- 有序集合、映射使用 `cc_rbt_core`；树的比较、复制、旋转等行为由 `CC_RbtOps` 回调提供，`user` 字段承载调用方上下文。
- 字符串长度使用 `CCUINT32` 时，源头必须检查不超过 `UINT32_MAX`。
- 文件大小、包内偏移使用 `CCUINT64`；窄化转换前检查范围。
- 所有公开写入接口在分配前检查整数溢出、容量上限和表示范围；不设置普通资源的固定硬上限，上限由格式或接口契约定义。
- 节点只保存职责所需的数据：键、树链接、类型、大小、时间、挂载归属等。与节点职责无关的外部元数据（命令历史、会话配置、显示状态等）由对应功能层保存。
- `CCDyn` 使用前清零：

```C
    CCDyn items;
    memset(&items, 0, sizeof(items));
```

- 分配数组时先做 64 位乘法，避免 32 位回绕：

```C
    CCFsStat *stats = (CCFsStat *)ccalloc(
        NULL,
        (CCUINT64)count * sizeof(CCFsStat),
        CC_DBG_REL_TAG("stat 数组", NULL)
    );
    if (!stats)
        return CCFALSE;
```

- 不把 `void *` 算术当作结构体遍历；需要按字节移动时显式转换为 `CCUINT8 *`。
- 未使用的参数用 `CC_UNUSED(v)` 标记，不用强制转换或空语句。

## 11. 错误处理

- 失败返回 `CCFALSE`，或返回明确的错误码。
- `ccfiles` 系列的错误以 `CCFsResult` 的负值返回，`CC_FS_OK` 为 0；读写接口成功时返回字节数，失败时返回负的错误码。
- `cc_dyn_core_push` / `pop` / `get` / `set` 返回 0 表示成功、1 表示越界或容量问题、-1 表示参数非法；`cc_dyn_core_seek` 越界时返回 0 并补零，只有参数非法返回 -1。
- `ccalloc` 失败返回 `NULL`；不设置全局错误码。
- 同一接口族保持一种返回约定，不混用 0/1 与负值。
- 参数非法、对象不存在、权限不足、IO 失败、空间不足分别给出可区分的错误，不折叠成一个“失败”。
- 首错终止：操作在第一个错误处停止，中间状态回滚，不提交半成品。
- 不吞错误；内层失败向上返回，由拥有上下文的层统一清理。
- 转换操作系统错误时保留原始类别：权限错误映射为 `CC_FS_ERR_PERM`，底层 IO 失败映射为 `CC_FS_ERR_IO`。
- 面向用户的错误信息由调用层组织，包含操作、对象（如路径）和原因；库层通过返回值表达错误类别。
- 不使用断言代替用户输入校验；断言只用于内部不变量，并在 RELEASE 下失效。
- 不静默截断：缓冲区不足、名称过长、范围越界都返回错误。

```C
    CCINT32 ret = ccfiles_stat(fs, v_path, &stat);
    if (ret != CC_FS_OK)
        return ret;
```

## 12. 测试代码

- 测试代码放在 `tests/`，按模块分文件；套件表在 `tests/test.c`，用例与断言接口在 `tests/test_harness.h`。
- 通过 `run_test.sh` / `run_test.bat` 运行套件；`all` 运行全部自动套件，`manual` 只运行人工确认项。
- 套件名使用大写短名，与模块对应：

| 套件 | 覆盖范围 | 测试源 |
|---|---|---|
| `BASIC` | 基础类型、atoi、crc、wildcard、时间 | `tests/basic.c` |
| `COLOR` | color_print 彩色输出 | `tests/color_print.c` |
| `PATH` | ccpath 路径工具 | `tests/ccpath.c` |
| `ENC` | cc_encoding 编码转换 | `tests/cc_encoding.c` |
| `HOST` | cchost 宿主文件操作 | `tests/cchost.c` |
| `HASH` | cc_hash 摘要计算 | `tests/cc_hash.c` |
| `RBT` | cc_rbt_core 红黑树内核 | `tests/rbt_core.c` |
| `DYN` | cc_dyn_core 动态数组内核 | `tests/dyn_core.c` |
| `ALLOC` | ccalloc 分配器 | `tests/ccalloc.c` |
| `THREAD` | ccthread 异步组件 | `tests/ccthread.c` |
| `FS` | ccfiles 统一文件管理 | `tests/ccfiles.c` |
| `NET` | ccnet 网络内核 | `tests/ccnet.c` |

- 用例编号使用 `模块-分组-序号`，全局唯一且不复用，例如 `FS-API-003`、`DYN-PUSH-001`。
- 每个用例用 `CC_CASE("编号", "名称")` 标记，用例内部用 `CC_CHECK`、`CC_CHECK_EQ_I64`、`CC_CHECK_EQ_U64`、`CC_CHECK_EQ_STR`、`CC_CHECK_MEM` 断言。
- 人工确认项用 `CC_MANUAL("编号", "名称")` 标记，只在交互终端中运行。
- 平台不适用时用 `CC_SKIP("原因")` 跳过，并说明原因。
- 测试 fixture 与临时目录由套件或用例创建并清理，放在构建输出目录下，不写入源码目录。
- 用例之间不依赖彼此遗留的状态；共享探针或临时目录的套件在套件级集中初始化与清理。
- 失败路径测试覆盖资源回滚、重复调用和错误码区分。
- 并发用例使用确定的种子；随机输入由 harness 的种子驱动。
- 测试只使用公开接口和测试确需的内部格式；库代码不包含测试专用分支。

## 13. 文档

- 模块文档放在 `docs/`，逐用例文档放在 `docs/tests/`，开发手册为 [开发手册](开发手册.md)，入口为 [快速入门](快速入门.md)，测试文档索引为 [tests 文档](tests/README.md)。
- 标题层级从 `#` 开始；一篇文档一个一级标题。
- 代码块标注语言：C 代码用 `C`，shell 用 `bash`，Windows 批处理用 `bat`，纯文本用 `text`。
- 文档只描述最终状态：接口行为、约束、所有权、平台行为与复杂度；不写变更历史或实施过程。
- 模块文档包含：职责、接口签名、参数与返回值、所有权、使用约束、复杂度、平台行为、示例和相关链接。
- 逐用例文档的每个条目使用 `## <编号> <名称>`，包含状态、前置、步骤、预期、真值来源、平台、级别和代码位置。
- 逐用例文档与测试代码一一对应：`docs/tests/ccfiles.md` 中的 `## FS-API-003 ...` 对应 `tests/ccfiles.c` 中的 `CC_CASE("FS-API-003", ...)`。
- 算法说明包含：输入、数据结构、步骤、复杂度、资源所有权。
- 开发手册的接口表列出每个模块及其文档链接；模块文档与测试文档互相链接。
- 使用相对链接，不写本机绝对路径。
- 正文使用中文；类型名、函数名、宏名、文件名用反引号包裹。

## 14. 格式检查清单

提交前自查：

- 4 空格缩进，无制表符，无行尾空格；
- 源文件为 UTF-8，换行为 LF；
- 花括号换行风格一致，`else` 不与 `}` 挤在一行；
- `case` 与 `switch` 同列，分支以 `break` / `return` / `goto` 结束；
- 多行调用按第 5 节闭合；
- 失败标签按资源阶段倒序释放；
- 确定非空资源不在清理标签中判空；
- 不依赖 `ccalloc(NULL, 0, NULL)` 兜底；
- 创建接口与释放接口成对出现，所有权在注释中写明；
- 只使用 `ccalloc`，分配失败有处理；
- 整数宽度使用 `CC` 类型，窄化前检查范围；
- 指针星号跟随变量，`sizeof` 带括号；
- 公共头使用 `_INCLUDE_..._H_`，内部头使用 `_SRC_..._H_` 或 `_INCLUDE_..._H_`，同一模块内统一；
- 公共头不暴露内部结构，内部头不进入公共头；
- 头文件、实现、文档、测试保持一致；
- Debug 与 Release 均通过，Release 在 `-Werror` 下无告警。
